## The complaint to fix

After the IA redesign (`ebdd58b..2424c67`) Alexey said: **"Now the site seems too crowded."**
The previous pass added structure (Verdict → Board → Evidence) but did not reduce visual load.
This pass's success criterion: **the same data, visibly less crowded.** Fewer simultaneous colors,
fewer competing numbers, clearer grouping. When in doubt, demote or collapse — never delete data.

## Current state (what exists — do not regress)

- Single static page generated by `site/generate.py` (+ `site/style.css`) from `data/*.json`. No JS build chain.
- Verdict ticket (winning route + sparkline + alternate), board with decision columns + expandable plumbing rows, evidence `<details>` (failures, official-compare, timeline), footer.
- Tokens: `--ink #0E1B2C` navy, `--paper #F7FAFC` ice, `--amber #FFB000` hikes/warnings, `--teal #2FBF9B` drops/healthy, `--red #E5484D` failures only. IBM Plex Mono for every number, IBM Plex Sans for copy.
- **Color law (enforced):** amber = price up / warnings, teal = price down / healthy, red = failures only, never decoration. One label = one job.
- Fresh today: projection basis — each route shows realized (bold) + dimmed "now" projection pair; verdict flips to projection automatically only when the backtest gate (≥80% of ≥20 transitions within 20%) passes. Median ask over 7d, EWMA-smoothed hit rates, marginal-realized $/M collection. Probe retry with `FLAKY-RECOVERED` evidence.
- Anti-staleness law: everything computed per render from data; nothing hardcoded.

## What this pass must achieve

1. **De-crowd.** Audit every simultaneously-visible element. The glance layer (ticket + board decision rows) should carry at most ~2 numbers per row that a scanner reads. Everything else is one interaction away.
2. **Regroup, don't restack.** Re-examine grouping: price-related things together, health-related things together, history together. Related columns/rows should read as one object, not as parallel lists.
3. **Phone parity.** Design 390px first for the glance layer; the board must not become a horizontal-scroll table on mobile.
4. **Projection pair done right.** The now-vs-30d pair must be understandable at a glance (which is now, which is 30d) without reading a caption.

## Hard constraints

- Pure static generation from `site/generate.py`; keep it that way (no frameworks, no npm).
- `python3 -m unittest discover -s . -q` must stay green (313 tests; wiring tests assert on rendered HTML).
- **Never dispatch probes or touch API keys. Rendering works offline from existing `data/`.**
- Vocabulary: "failures" never "errors"; follow `ONTOLOGY.md` terms.
- No external font/CDN dependencies added without self-hosting consideration (page must work offline).

## Design-skill laws to obey (frontend-design + impeccable)

- **Product register** — design SERVES the tool. Earned familiarity is the bar, distinctiveness within discipline.
- Spend boldness in ONE place (currently the ticket). Everything else quiet.
- Bans: side-stripe borders, gradient text, glassmorphism, hero-metric template, identical card grids, eyebrow-on-every-section, numbered markers without a real sequence, `border-radius: 32px+`, decorative grids, `repeating-linear-gradient`, 1px-border+16px-blur-shadow on one element.
- Contrast ≥4.5:1 body text; tinted neutrals (0.005–0.015 chroma toward ink hue); OKLCH acceptable for new tokens.
- Motion: one orchestrated moment max, ease-out exponential curves, `prefers-reduced-motion` respected, never gate visibility on a transition.
- Body line length 65–75ch; `text-wrap: balance` on headings; no text overflow at any breakpoint.
- Copy: sentence case, active verbs, one label = one job, errors never apologize.
