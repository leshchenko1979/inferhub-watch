## Mission (owner order 2026-09-10 07:0xZ: "One of the aims of the project is to provide timely updates on routes with bigger IQ per projected price")

**The project exists to let the owner extract the best value/price ratio from the Inferhub inference auction.** Concretely: timely updates on **routes with bigger IQ per $** (per `ONTOLOGY.md`) — high-IQ routes at low ask are the candidates worth surfacing first.

- **Value signal, not just health signal.** Sweep/probe data is not only monitored for freshness (surface sanity) — it is ranked: route comparisons should lead with **IQ per $** (IQ score ÷ official ask) so the owner can act on the auction, not just watch it.
- **Timeliness is part of the mission.** "Timely" binds the observation-surface cadence: dashboard data currency (cycle step 5 leg b, refreshed hourly by the `inferhub-usage-logs-sync` cron) and sweep health (step 3) are mission-critical, not hygiene — a stale ranking is a failed mission output even when all systems are green.
- Surface work that adds IQ-per-$/value ranking to Grafana or the Pages site is **mission work** — priority over cosmetic improvements, still dispatched per the delegation law.
- In cycle reports and worker briefs: when the data supports it, report the current top routes by IQ per $ alongside the health verdict.

## Ontology law (hard)

Every report, issue, and commit uses the codified terms from `ONTOLOGY.md` exactly: **route, probe, sweep, board, verdict, ask, floor ask, hit rate, cache rule, failure, attempt, window, snapshot, candidate, IQ per $.**

An earlier version of this bullet called `fef19c4f` the **SOLE production switching authority** — that was WRONG (issue #26's "no executor" finding is retracted; see the ledger). Both paths run the script's own gates, update OpenCrabs config + sessions, and send their own Telegram switch alert on a real switch. HQ hourly cycles stay **dry-run-only** (observation, never mutation). NOOP cycles are silent; failures escalate to the owner topic with a 🔴 marker. Spend gate pre-approved by the owner (floor delta ≈ +$33/mo worst case, ~+$70-88/mo realized). Neither path passes `--no-notify` (the script's own alert is the owner notification) and neither hand-edits config.toml — the script owns config writes.
  - **One basis per comparison (basis consistency).** A switch decision ranks every candidate on **one** money basis. `select_basis()` returns the realized basis only when **every** candidate carries ≥ `BASIS_MIN_SAMPLES` (5) realized samples; otherwise the decision is made on the **floor** basis (`apply_basis`). The incumbent joins the candidate pool for the basis test, so a partially-populated realized set can never be ranked against a floor-basis challenger. Each switch reason carries `basis=<floor|realized>` and the alert carries `Basis:`/`Dwell:` lines. Rationale: the 07:15Z/07:24Z thrash pair came from comparing a realized ask against a floor ask — two different units in one ranking. `basis=floor` names the **traffic-independent basis family**, not the raw ladder point: `resolve_floor_price()` returns `basis.projected(...)` whenever the crown gate passes, else the catalog floor ask (live 2026-09-12: projected `4.66e-05` vs ladder floor eff `0.004635` — 99.5× apart, which is why a floor-basis Val runs to 7.6e5). It stays consistent because `apply_basis()` puts that same price on EVERY candidate.
  - **Dwell gate.** A switch needs ≥ `DWELL_SECONDS` (**6 h**) since the last switch, unless the gain exceeds `DWELL_OVERRIDE_GAIN` (**3×**), both overridable with `--dwell-hours` / `--override-gain`. State lives in `data/switcher_state.json` (gitignored), written **before** the notification so a failed alert cannot lose dwell state. **Missing or unparseable state leaves the gate OPEN** — a corrupt state file must never block a legitimate switch, and must never be hand-created.
  - **Pinned floor point.** A route's floor ask is a single deterministic function of its ladder, owned by `probe/floor.py` (`floor_point()`: cheapest point with publisher count ≥ 1, ties to the larger count). `probe/pricing.py`, `probe/catalog.py` and the switcher all read that one number; `sync_route_metrics` logs the selected point per route per pull and flags a `FLOOR FLIP` against the stored row. Never re-derive a floor with a bare `min()` over ladder points — that publishes advertised-but-unfilled prices.
  - **Realized asks are not trustworthy on their own.** `cb/deepseek-v4.1-flash`, `ag/gemini-3.7-flash-high` and `ag/gemini-3.8-flash-high` record realized asks at exactly `official / 1000` — a fixed function of the rate card, not a market observation, and 9–30× below the cheapest ladder point their publishers offer (verdict: [`reports/2026-09-12-issue-27-realized-ask-verdict.md`](https://github.com/leshchenko1979/inferhub-watch/blob/main/reports/2026-09-12-issue-27-realized-ask-verdict.md)). Treat a realized ask at exactly `official / 1000` as unverified; it must not be the value that selects the realized basis.
  - **RE-ARM CRITERIA (the cron stays `enabled=false` until all four hold):** (1) ✅ all four #27 items landed in `main` with tests; (2) ✅ a verified dry-run shows **stability across two consecutive synthetic basis shifts** — [`scripts/basis_shift_harness.py`](https://github.com/leshchenko1979/inferhub-watch/blob/main/scripts/basis_shift_harness.py) forces floor → realized → floor on fixtures and emits **no switch on either shift** (both receipts + the pre-#27 mixed contrast: ledger 2026-09-12 08:1xZ); (3) ✅ the floor-point receipt names a real filled ladder point for the fleet default on a live pull (`0.0045@1p`); (4) ⏳ the owner is told the outcome before the cron is enabled. **Scoreboard 3/4.** Re-arming is an owner-gated action: report the four receipts, do not enable it yourself.
